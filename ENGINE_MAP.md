# خريطة محرك المحاسبة الكاملة
`Invoice → Posting → Inventory → COGS → Return → Receivable/Payable → Receipt/Payment → FX Difference → Reports`

كل مرحلة: الدالة المسؤولة، والقاعدة المحاسبية، ومرجع الاختبار الذي يثبتها.

```
┌─────────────────────────────────────────────────────────────────────┐
│ 1. Invoice (فاتورة شراء/بيع)                                         │
│    عملة واحدة + سعر صرف واحد وقت الترحيل (WORKFLOW.md §42.1)         │
│    compute_invoice_totals() — المصدر الوحيد لإجمالي الفاتورة         │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 2. Posting (الترحيل)                                                  │
│    post_purchase_invoice() / post_sales_invoice()                    │
│    _jline (raw×rate) لكل ما بعملة المستند، _jline_base لما هو أساسي  │
│    مسبقاً (COGS) — الخلط بينهما كان مصدر خطأ §29-§30                  │
│    حارس اتساق تلقائي: assert_reasonable_conversion (sanity_guard.py) │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 3. Inventory (المخزون)                                                │
│    InventoryMovement.unit_cost = تكلفة تاريخية ثابتة وقت الحركة،      │
│    لا تُعاد تسعيرها لاحقاً أبداً (قاعدة §39: "التاريخ لا يُعاد          │
│    تسعيره بأثر رجعي")                                                 │
│    get_item_stock_summary() تستخدم unit_cost المخزَّن لكل حركة خروج   │
│    (لا متوسطاً مُعاد حسابه — إصلاح §39.2)                             │
│    Weighted Average Perpetual: كل IN يحدّث المتوسط، كل OUT يسحب       │
│    بتكلفته الخاصة المخزَّنة على الحركة نفسها                          │
│    التكلفة منفصلة لكل مستودع (§46) — لا موحّدة على مستوى الشركة.      │
│    get_item_stock_summary(warehouse_id=None) = عرض تجميعي شرعي        │
│    للتقارير فقط. _average_cost() تفرض warehouse_id إلزامياً لكل       │
│    قرار تسعير/ترحيل فعلي. Transfer بين مستودعين يحمل متوسط المصدر     │
│    الحالي، يندمج طبيعياً بمتوسط الوجهة (لا "نفس السعر يبقى منفصلاً")  │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 4. COGS (تكلفة البضاعة المباعة)                                       │
│    عند البيع: _average_cost() وقت البيع تحديداً (لا لاحقاً)           │
│    فاتورة متعددة المواد → COGS منفصل لكل حساب مادة (إصلاح §27)        │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 5. Return (المرتجع) — post_return() [returns.py]                     │
│    حدث تجاري جديد، يؤثر على متوسط التكلفة المستقبلي                  │
│    مرتجع مرتبط بفاتورة أصلية → يستخدم unit_cost الحركة الأصلية         │
│    (تاريخي)، لا المتوسط الحالي وقت الإرجاع — حتى لو تغيّر سعر الصرف    │
│    (§39، test_aggressive_currency_inventory.py مجموعة 3 + الإضافة)   │
│    ≠ Cancel/Reverse (فئة D-6 — محسومة الآن §44: cancel_invoice()      │
│    [invoice_cancel.py] — عكس حرفي بالقيم التاريخية، يُرفَض مع أي       │
│    تسوية مرتبطة، 15/15 تحققاً)                                        │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 6. Receivable/Payable (الذمم)                                         │
│    فاتورة آجلة (is_cash=False) → get_or_create_party_account()       │
│    الرصيد المستحق balance_due يُحسَب ديناميكياً دائماً (§42.1) —       │
│    لا حقل مخزَّن قد يفقد تزامنه: = compute_invoice_totals().grand_total│
│    ناقص مجموع Settlement.amount_foreign المرتبطة                     │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 7. Receipt/Payment (القبض/الدفع) — settlements.py [جديد §42-43]      │
│    post_receipt() / post_payment()                                    │
│    Invoice → Settlement → JournalEntry (دفعات جزئية متعددة ممكنة)     │
│    كل تسوية = (amount_foreign بعملة الفاتورة, settlement_rate)        │
│    القيمة الأساسية الفعلية = amount_foreign × settlement_rate         │
│    سطر الذمم يُقفَل بسعر الفاتورة الأصلي (invoice.exchange_rate)،     │
│    لا سعر التسوية — الفرق بينهما هو فرق الصرف بالضبط                  │
│    رفض: تجاوز الرصيد المستحق / فاتورة CANCELLED أو DRAFT / فاتورة نقدية│
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 8. FX Difference (فرق الصرف) — محقَّق عند التسوية فقط                 │
│    fx_diff = (amount_foreign×settlement_rate) − (amount_foreign×      │
│    invoice.exchange_rate)                                             │
│    عميل: فرق موجب=ربح. مورد: فرق موجب=خسارة (إشارة معكوسة)            │
│    حسابان منفصلان: fx_gain (4103) / fx_loss (6106) — لا حساب مشترك    │
│    IAS 21 إعادة التقييم الدوري للأرصدة غير المسواة: مؤجَّلة صراحة،     │
│    غير مُنفَّذة (فئة D-5 بـREVIEW_REPORT.md)                          │
└───────────────────────────┬─────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 9. Reports (التقارير)                                                 │
│    ميزان المراجعة / قائمة الدخل / الميزانية — بالعملة الأساسية حصرياً  │
│    (سطر مستقل بكل عملة للعميل/المورد: مؤجَّل، فئة D-2)                │
│    get_account_statement() يستخدم debit_base/credit_base حصرياً —     │
│    لا جمع خام لعملات مختلطة (آمن تقنياً، غير مُختبَر بعمق — فئة B)     │
│    ⚠️ اكتشاف §48: لا base_currency داخل قاعدة الشركة نفسها (فقط        │
│    بـregistry.db المنفصلة) — خطر حالي منخفض الأثر (تسمية لا حساب،      │
│    راجع REVIEW_REPORT.md)                                             │
└─────────────────────────────────────────────────────────────────────┘
```
